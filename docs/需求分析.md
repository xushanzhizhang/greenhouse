# 智慧大棚数字孪生大屏 · 需求分析与设计说明

| 项 | 内容 |
| --- | --- |
| 项目名称 | 智慧大棚数字孪生平台（大屏端） |
| 文档版本 | v1.0 |
| 编制日期 | 2026-11-18 |
| 三维资产 | `model/greenhouse_optimized.glb`（由 `Greenhouse.fbx` 转换，27.5 MB） |

## 1. 项目概述

### 1.1 背景

大棚环境调控目前依赖分散的传感器读数和人工经验，缺乏一张能同时表达"空间位置 + 实时状态 + 装备动作"的总览界面。园区已有的温室 FBX 模型（16 m × 32.16 m 主体、高 6.8 m，含 4 个种植分区与 32 棵园区装饰树）为大屏提供了真实空间基底，但模型本身只是"静态外壳"，不能回答"哪个区现在多少度、哪台设备在跑、哪里在报警"。

本项目要做的，是把模型变成**可读的运行态孪生体**：以三维场景为空间索引，把环境、装备、作物、资源、告警五类数据挂到对应的位置和分区上，形成一屏可判读的态势界面。

### 1.2 建设目标

1. **一屏总览**：值班人员在 3 秒内看清"棚内环境是否正常、设备是否按策略运行、是否有待处理告警"。
2. **空间可读**：温度、湿度、CO₂ 等关键指标与棚内四个分区一一对应，点击模型即可联动该区数据。
3. **态势可信**：数据具备连续性与物理合理性（日夜节律、执行器影响、土壤水分收支），而非随机跳变的假数字。
4. **开箱可演示**：断网、无后端、无账号条件下，双击一次即可全屏呈现，适合汇报、参观与教学演示。
5. **留有接口**：数据层与 UI 层解耦，后续替换为 MQTT/WebSocket 真实数据时不需要改界面代码。

### 1.3 范围边界

| 纳入本期 | 不纳入本期 |
| --- | --- |
| 三维孪生场景展示、视角控制、分区联动 | 真实传感器硬件接入与网关部署 |
| 环境/装备/作物/资源/告警五类面板 | 历史数据仓库与报表导出 |
| 24 小时趋势、分区适宜度图表 | 用户权限、多角色、审批流 |
| 内置物理合理的模拟数据源 | 视频监控流接入、AI 病虫害识别 |
| 一键启动、全屏适配 | 移动端/小程序适配 |

## 2. 用户与场景

| 角色 | 关注点 | 典型动作 |
| --- | --- | --- |
| 值班员（主） | 当前是否异常、设备是否在跑 | 扫视告警栏、点选分区核对数值、必要时远程启停 |
| 园区管理者 | 当日资源消耗、作物长势 | 查看资源卡与作物卡、对比分区适宜度 |
| 参观/评审人员 | 整体观感、技术含量 | 观看自动巡航、切换视角、观察实时数据跳动 |
| 运维人员 | 数据链路是否健康 | 查看系统状态卡（延迟、完整率、运行时长） |

**典型场景**：指挥中心 55 寸以上大屏常驻显示，无人交互时自动巡航；有人讲解时通过"全景/大棚/棚内/俯视"四个预设切换视角，点击棚体或分区标签联动左侧面板。

```

│ 顶栏 78px  品牌 / 4 项 KPI / 天气·时钟·全屏                    │
├────────────┬──────────────────────────────┬──────────────────┤
│ 左列 392   │ 中列（自适应，约 1076）        │ 右列 392         │
│ 环境监测    │ 三维孪生视口                  │ 实时告警          │
│ 装备运行    │ · 分区标签 / 视角按钮          │ 作物生长          │

├────────────┴──────────────────────────────┴──────────────────┤
│ 底部 200px  24 小时环境趋势（1.55fr） | 分区适宜度雷达（1fr）   │

```

- 整屏按 1920×1080 绝对布局，`transform: scale(min(vw/1920, vh/1080))` 等比缩放并居中。
- 左右列固定 392px，中列吃掉剩余宽度；所有卡片等高拉伸、内部滚动，保证 1080P 下无裁切。

### 3.2 视觉基调

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 背景 | `#02060d` → `#0a1826` | 深空蓝黑，降低大屏环境光干扰 |
| 主色（数据/边框） | `#3ee7ff` | 冷青，用于常规数据与描边 |
| 正常/运行 | `#49f0a6` | 设备运行、作物进度 |
| 预警 | `#ffbe4d` | 湿度偏低、CO₂ 偏高 |
| 严重 | `#ff5f6d` | 高温、缺水 |
| 辅助 | `#a98bff` | 资源类指标 |

字号层级：主标题 27 / 卡片标题 15 / 数值 21–26（Bahnschrift）/ 标签 11 / 辅助 9.5–10。

动效原则：数值变化用 0.6s 过渡，卡片不整体闪烁；告警条目滑入 0.35s；三维场景只做脉冲环与粒子缓慢漂移，避免大屏长时间观看的视觉疲劳。

## 4. 功能需求

优先级：P0 = 演示必需，P1 = 完整度必需，P2 = 增强。

### FR-01 三维孪生场景加载与呈现（P0）

- 加载 `greenhouse_optimized.glb`，加载期间显示进度条与百分比，完成后淡出遮罩。
- 模型自动做包围盒归一：底部贴合 `y=0`、水平居中，避免手工调坐标。
- 材质处理：玻璃统一替换为低不透明度物理材质（opacity 0.20、双面、不写深度）以透出内部苗床；植被保留 alpha 裁剪；贴图开启各向异性过滤。
- 光照：半球光 + 主平行光（随真实时刻移动）+ 冷色轮廓光；夜间自动点亮棚内暖光，背景与雾色同步压暗。
- 场景基座：同心网格环、36 格辐射线、加法混合光晕，形成"数字孪生底盘"。
- **验收**：加载完成 < 15 s（本地服务），场景可见且无穿模、无材质黑块。

### FR-02 视角控制与预设（P0）

- 四个预设：全景、大棚、棚内、俯视；切换时相机位置与目标点做 1s 缓动插值，不硬切。
- 轨道控制：左键旋转、滚轮缩放（7–130 m）、限制俯仰角避免钻地。
- 自动巡航开关：默认开启，0.45 倍速环绕；手动拖拽后仍保持巡航（可关闭）。
- **验收**:四个预设均可到达且构图完整；巡航无明显抖动。

### FR-03 分区热区标注与联动（P0）

- 四个分区（A1 番茄 / A2 黄瓜 / A3 草莓 / A4 生菜）在三维空间对应一条垂直光柱 + 地面温度色环 + DOM 投影标签。
- 标签内容：分区号、实时温度、湿度、CO₂，随相机投影实时跟随；背向相机时自动隐藏。
- 点击标签或点击棚体（射线拾取后按 Z 轴就近归区）→ 左侧环境面板、作物卡、雷达高亮同步切换。
- 温度色环按 14→33℃ 做蓝→青→绿→黄→红色阶映射，图例常驻右上。
- **验收**：点击任意分区，三处面板与标签高亮一致，响应 < 100 ms。

### FR-04 环境监测面板（P0）

- 展示选中分区 8 项指标：空气温度、空气湿度、CO₂、光照、土壤温度、土壤含水率、基质 EC、基质 pH。
- 每项含数值、单位、量程进度条与状态色（正常/预警/严重），阈值来自 `config.js` 的统一口径。
- 刷新频率 1 Hz；数值保留位数按指标定义（温度 1 位、EC/pH 2 位、光照取整）。
- **验收**：8 项指标齐全，越限时颜色与进度条同步变化。

### FR-05 装备运行与远程启停（P1）

- 9 台设备：循环风机 A/B、湿帘水泵、LED 补光灯、外遮阳幕、内保温幕、水肥滴灌、加温管道、CO₂ 发生器。
- 每行显示图标、名称、运行状态、累计运行时长/额定功率；点击整行即切换启停，带状态灯与开关动效。
- 启停真实影响模拟数据（湿帘降 1.6℃、升 6.5% 湿度；加热升 1.8℃；补光灯补 2600 lux 等），不是纯装饰。
- **验收**：点击后开关状态、运行计数、环境读数在 3 s 内出现可感知变化。

### FR-06 实时告警中心（P0）

- 分级：严重（红）/ 预警（黄）/ 提示（青）；每条含分区、时刻、文案。
- 规则引擎每 5 s 巡检 9 条阈值规则（高温、低温、高湿、低湿、CO₂ 偏高、土壤缺水/过湿、EC 偏高、pH 偏低），同区同规则 2 分钟内不重复推送。
- 保留最近 12 条，面板显示前 6 条，顶部统计未处理数量。
- **验收**：开关设备或调整环境后能触发对应告警，文案含分区与数值方向。

### FR-07 作物生长态势（P1）

- 按选中分区展示：作物名称、生育阶段、进度条、播种天数、有效积温（℃·d）、叶面积指数、预估产量（t/亩）、长势评分。
- 数据来自作物档案（番茄 78 天/开花坐果期、黄瓜 64 天/结果盛期、草莓 96 天/果实膨大期、生菜 32 天/莲座期）。
- **验收**：切换分区时四个字段同步；进度条与百分比一致。

### FR-08 资源消耗（P1）

- 今日用电（kWh）、灌溉用水（m³）、CO₂ 施放（kg），各含目标值与完成百分比进度条。
- 用电按"当前开启设备额定功率之和 × 时间"累计，用水按滴灌 1.2 m³/h、CO₂ 按 0.45 kg/h 累计，保证与设备状态自洽。
- **验收**：开启加温管道后用电增速明显上升。

### FR-09 趋势与适宜度图表（P1）

- 左图：24 小时空气温度（面积线，左轴℃）与空气湿度（虚线，右轴 %RH），5 分钟粒度、288 点，开屏即有完整曲线。
- 右图：四分区在"温度适宜/湿度适宜/光照满足/CO₂ 适宜/土壤水分"五维上的雷达对比（0–100 归一）。
- 图表每 5 s 更新，避免 1 Hz 重绘带来的 CPU 占用。
- **验收**：曲线连续无断点；雷达四色可区分；缩放窗口后图表自适应。

### FR-10 系统状态（P2）

- 采样频率 1 Hz、网关延迟（12–18 ms 波动）、数据完整率 99.8%、连续运行时长（按启动时刻计算）。
- **验收**：运行时长随时间递增，刷新页面不重置（按固定启动时刻扣除）。

### FR-11 全屏与自适应（P0）

- 顶栏全屏按钮调用 Fullscreen API；启动脚本默认以 Chrome kiosk 全屏打开。
- 任意 16:9 分辨率等比缩放，不出现拉伸与滚动条；非 16:9 时按短边等比并留黑边。
- **验收**：1920×1080、2560×1440、3840×2160 下布局无错位。

### FR-12 数据源可替换（P2）

- 数据层 `GreenhouseModel` 对外只暴露 `snapshot()` 与 `onChange()`；模拟源与真实源实现同一契约。
- 真实接入时新增 `WebSocketSource`，把报文映射为同结构的 `zones/devices/alerts`，UI 与三维层零改动。
- **验收**：`data.js` 中替换实现后，页面其余文件不需修改。

## 5. 非功能需求

| 类别 | 指标 | 说明 |
| --- | --- | --- |
| 首屏 | 本地服务下模型可见 < 15 s | 27.5 MB GLB + 1024 贴图，避免 2048 贴图在 2 GB 显存上反复换页 |
| 帧率 | GT730 2G / i7-10700 下 ≥ 30 FPS，目标 45 FPS | 关闭阴影贴图、像素比上限 1.75、粒子 220、无后期处理 |
| 内存 | 稳定运行 8 h 内存增长 < 10% | 历史定长 288 点、告警定长 40 条、图表不累积实例 |
| 稳定性 | 7×24 常驻不崩溃、不弹窗 | 无外部网络依赖，全部资源本地化 |
| 兼容性 | Chrome / Edge 最新版（WebGL2） | 不支持 IE 与国产双核浏览器兼容模式 |
| 可维护性 | 配置与表现分离 | 分区、指标、设备、阈值集中在 `js/config.js` |
| 可移植性 | 拷走 `D:\greenhouse` 即可运行 | 依赖已 vendor 到 `web/vendor`，不需要 npm install |

**已知约束**：GT730 属入门独显，23 万三角面 + 大面积半透明植被叠加时，棚内视角帧率会下降；已通过禁用阴影、限制像素比、植被 alpha 裁剪缓解。若后续加入视频流或多场景，需升级显卡或改用云渲染。

## 7. 技术架构

### 7.1 分层

```
┌─────────────────────────────────────────────────────┐
│ 表现层  web/index.html + css/screen.css              │
│         ├─ 三维视口  js/scene.js（Three.js）          │
│         └─ 数据面板  js/ui.js（DOM + ECharts）        │
├─────────────────────────────────────────────────────┤
│ 数据层  js/data.js（GreenhouseModel 模拟引擎）         │
│         契约：snapshot() / onChange() / toggleDevice() │
├─────────────────────────────────────────────────────┤
│ 配置层  js/config.js（分区·指标·设备·阈值·色板）        │
├─────────────────────────────────────────────────────┤
│ 资产层  model/*.glb  web/vendor/*（three、echarts）   │
├─────────────────────────────────────────────────────┤
│ 运行层  server.mjs 或 py -m http.server + Chrome kiosk│
└─────────────────────────────────────────────────────┘
```

### 7.2 数据流

```
模拟引擎 tick(1s)
  → 目标值(日变化+执行器) → 一阶惯性跟随 → 分区 state
  → snapshot() 广播
      ├─ scene.updateData()：标签数值、温度色环、设备发光、昼夜光照
      └─ ui.update()：KPI、指标卡、作物、资源、告警；图表 5s 节流
```

### 7.3 资产管线

| 步骤 | 工具 | 处理 | 结果 |
| --- | --- | --- | --- |
| 1 | Blender 4.5 无头导入 | FBX 原始 135 网格 / 232,684 三角面 | 场景树还原 |
| 2 | 材质重建 | 原始 `Plants` 材质缺失贴图（苗床呈灰白），补绑 Diffuse / Opacity / Normal / Roughness | 苗床还原真实植物质感 |
| 3 | 贴图降采样 | 11 张 2048 → 1024，重新打包 | 显存占用约降至 1/4 |
| 4 | 材质修正 | HASHED → CLIP（alpha 0.5），导出后强制植被 alphaMode=MASK | 植被镂空正确，避免半透明排序错乱 |
| 5 | glTF 导出 | 内嵌贴图、Y-up、不压缩几何 | `greenhouse_optimized.glb` 27.5 MB |

> 说明：FBX 直接进浏览器需要额外解析贴图相对路径，且 43 MB 原始文件解析更慢；转 GLB 后单文件加载、路径零依赖，更适合大屏离线运行。原始 FBX 保留在 `model/source` 作为回滚备份。

## 8. 部署与运行

### 8.1 环境要求

- Windows 10/11，Chrome 或 Edge（WebGL2）。
- Python 3.7+ 或 Node 18+（仅用于起静态服务，二选一）。

### 8.2 启动

1. 双击 `启动大屏.bat`：自动选择 `py -m http.server` 或 `node server.mjs` 起服务（端口 8090），随后以 kiosk 全屏打开 Chrome。
2. 退出全屏：`Alt + F4` 或 `F11`；关闭标题为 `greenhouse-server` 的最小化窗口即停止服务。
3. 手动方式：`py -3 -m http.server 8090 --directory D:\greenhouse`，浏览器访问 `http://localhost:8090/web/index.html`。
4. 换端口：修改 bat 中 `PORT`，或 `node server.mjs 8091`。

### 8.3 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 白屏、控制台报 module 404 | 用 `file://` 直接打开 | 必须走 http 服务，ES Module 不允许 file 协议 |
| 模型不显示、加载停在 0% | 端口被占用或服务未起 | 换端口，确认 `http://localhost:8090/web/index.html` 可访问 |
| 场景很卡 | 显卡不足或像素比过高 | 关闭其他 GPU 程序；如需再降负载，可将 `scene.js` 像素比上限调至 1.2 |
| 文字模糊 | 缩放后位图拉伸 | 使用 1920×1080 或 3840×2160 等 16:9 整数倍分辨率 |

## 10. 风险与后续扩展

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| GT730 显存与算力有限 | 棚内视角帧率下降 | 已降贴图/关阴影；后续可换 GLB 的 LOD 或升级显卡 |
| 模拟数据与真实偏差 | 演示可信度 | 数据层已抽象，接入真实网关后以实测为准 |
| 大屏长期无人值守 | 服务中断无人发现 | 建议加开机自启与进程守护（任务计划程序） |
| 模型版权 | 商用受限 | 现有模型为免费资源，正式项目需替换为实测模型 |

**后续扩展优先级**：

1. **真实数据接入**（P0）：ESP32/网关 → MQTT → WebSocket 桥 → `WebSocketSource`。
2. **视频融合**（P1）：在三维场景中贴摄像头画面，形成"虚实对照"。
3. **策略联动**（P1）：告警一键触发设备组合（如高温 → 开湿帘 + 开风机）。
4. **多棚切换**（P2）：园区级视角下点击不同温室进入单棚。
5. **移动端只读版**（P2）：值班人员手机查看关键 KPI 与告警。
